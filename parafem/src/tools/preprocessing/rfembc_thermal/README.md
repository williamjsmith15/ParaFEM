# rfembc_thermal

Preprocessing tool for the RFEM (Random Finite Element Method) thermal/diffusion pipeline.
Reads a structured hex mesh and generates Dirichlet boundary condition files for
steady-state scalar problems (temperature, gas concentration, etc.).

## Relationship to rfembc

`rfembc_thermal` is derived from `rfembc` but targets `nodof=1` scalar problems
(single DOF per node) rather than structural analysis. Key differences:

- Applies BCs to both `zmax` (upstream) and `zmin` (downstream) faces simultaneously
- Writes all fixed freedoms in ascending node number order (required by `find_no2`)
- Sets `nr=0` in the output `.dat` — all BCs are Dirichlet via penalty method, no `.bnd` needed

## Usage

```
rfembc_thermal <job_name> <val_upstream> <val_downstream>
```

`<job_name>` is the base name shared by the input files (no extension).

`val_upstream` is applied to nodes on the `zmax` face; `val_downstream` to `zmin`.

For thermal problems: `val_upstream` = hot temperature, `val_downstream` = cold temperature.
For diffusion problems: `val_upstream` = upstream concentration (from Sievert's law),
`val_downstream` = 0 (vacuum downstream).

## Input files

| File | Contents |
|------|----------|
| `<job_name>.dat` | Solver control parameters (rfemsolve format from rfemcube) |
| `<job_name>.d` | Nodal coordinates and element connectivity |

## Output files

| File | Contents |
|------|----------|
| `<job_name>.fix` | Fixed freedoms — all zmax and zmin nodes, ascending node order |
| `<job_name>.dat` | Updated control file with `nr=0` and correct `fixed_freedoms` count |
| `<job_name>.res` | Summary: node counts, z extents, BC values, number of fixed freedoms |

## `.fix` file format

Each row: `<node>  1  <value>`

The sense is always `1` (only DOF for scalar problems). Nodes are written in
strictly ascending order, which is required by the `find_no2` binary search
routine used by `rfemsolve_thermal`.

## Notes

- Both faces are written to `.fix`; nodes must not also appear in `.bnd` (see p123 BC rules)
- The output `.dat` file always has `nr=0` — `rfemsolve_thermal` uses penalty method only
- This tool is designed to work with meshes generated by `rfemcube`
